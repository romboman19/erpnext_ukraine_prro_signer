# Security policy

- signer повинен бути доступний лише з приватної мережі ERPNext;
- `API_KEY` — окремий випадковий секрет щонайменше 32 символи;
- КЕП і пароль не логуються та не зберігаються signer-ом;
- не монтуйте каталоги з ключами у контейнер signer;
- `ALLOW_TEST_TIME` у production заборонений;
- оновлення приймайте лише після `npm test`, `npm audit` і Docker healthcheck.

Підозру на компрометацію ключа треба обробляти як інцидент КЕП: негайно
відкликати сертифікат у КНЕДП, деактивувати `UA KEP Key`, змінити API key,
перевірити PRRO/terminal ledgers і зареєструвати новий ключ у ДПС.
